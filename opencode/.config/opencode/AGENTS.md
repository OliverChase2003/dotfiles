# Global OpenCode Rules

## 沟通

- 默认使用中文，除非我明确要求使用英文。
- 回答应简洁、直接、务实。
- 回答应简洁易懂。
- 使用书面化语言，杜绝娱乐化表达（例如：补刀、揪出来、不用猜）。
- 仅在我明确需要更多方案时，提供更多思路。
- 修改前先阅读相关代码和配置，避免推测。
- 当存在阻碍、权衡或假设会影响结果时，应明确说明。

## 编辑

- 仅修改工作目录中的文件。
- 保留已有的项目风格和结构。
- 优先采用最小化的正确修改。
- 除非有明确需求，否则不添加新依赖。
- 除非有实际需求，否则不引入抽象层或兼容代码。
- 避免修改无关文件。

## 验证

- 修改后，在可行的情况下进行针对性验证。
- 优先使用最小相关的测试、lint 或 build 命令，而非大范围的检查。
- 若无法运行验证，应明确说明原因。

## Git

- 除非我明确要求，否则不创建提交。
- 除非我明确要求，否则不还原或覆盖已有的用户更改。
- 默认将未提交的更改视为有意为之。

## 决策

- 当存在多个可行方案时，优先选择更简单、更易维护的方案。
- 仅在歧义会实质性影响实现时，才提出简短的澄清问题。
