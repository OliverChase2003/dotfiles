# Global Pi Agent Rules

## 沟通

- 默认使用中文，除非明确要求使用英文。
- 回答保持简洁、直接、务实。
- 使用书面化技术语言，避免娱乐化表达。
- 优先给出结论，再说明原因。
- 当存在阻碍、权衡或关键假设时，明确说明。
- 不确定时不要猜测，说明不确定性。

## 代码修改

- 修改文件前，先阅读相关代码、配置和上下文。
- 仅修改当前工作目录中的文件。
- 保留已有代码风格、目录结构和设计约定。
- 优先采用最小化、局部、正确的修改。
- 除非明确需要，否则不要：
  - 添加新的依赖
  - 引入新的抽象层
  - 重构无关代码
  - 修改公共接口
- 避免为了未来可能需求提前设计。

## 工作流程

执行任务时：

1. 分析现有代码和项目结构。
2. 说明计划或关键修改点。
3. 进行必要修改。
4. 运行适当的验证。
5. 总结修改内容和验证结果。

## 验证

- 修改后，在条件允许时运行相关验证。
- 优先运行最小范围验证：
  - 单元测试
  - lint
  - build
  - 类型检查
- 不运行明显无关的大规模检查。
- 如果无法验证，说明原因。

## Git

- 不主动创建 commit。
- 不主动执行 push。
- 不主动 reset、checkout 或覆盖用户修改。
- 将未提交修改视为用户有意保留。
- 修改前注意 git diff，避免覆盖已有工作。

## 决策

- 多个方案可行时，优先选择：
  - 简单
  - 可维护
  - 符合当前项目风格

- 只有当选择会明显影响实现结果时才询问。
- 对小问题自行选择合理方案。

## 文件操作

- 除非明确要求，不删除文件。
- 除非明确要求，不移动文件。
- 修改范围保持最小。
